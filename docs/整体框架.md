## 二、核心数据模型：招标主表（唯一数据源）

文件：`data/bidding/master_bids.json`（源）+ 每次运行导出 `.xlsx` 存档。

列（用户可见）：
`序号 | 项目名称 | 预计发布公告时间 | 发布时间 | 开标时间 | 投标单位 | 状态(已投/放弃/在投)`

内部附加字段：`命中关键词 | 来源 | 公告链接 | 去重键(项目名称+时间规范化) | 备注`

读写规则：
- ① 上传生成/重建主表初版（去重：项目名称规范化）。
- ② 每日抓取后按去重键合并：已存在跳过、新公告追加，自动补"发布时间/开标时间"。
- ③ 只读，筛选"开标时间 == 明日"。
- 投标单位、状态：不自动抓取，**由用户文字登记 → LLM/规则解析 → 写回主表**。

## 三、运行与调度架构

```
[GitHub 仓库 = 单一数据源（历史/主表/报告随运行 commit）]
  ├─ .github/workflows/*.yml   每日定时(09/16/17/18时) + workflow_dispatch 手动
  │     python 脚本 → 更新 data/ → git commit → Server酱推送个人微信
  ├─ jobs/                     5 个助手执行脚本（共享抓取/筛选/推送/LLM 库）
  ├─ data/                     主表、历史、分析报告产物
  └─ apps/web                  本机网页工作台
        Vue3 + Vite 暗黑科技 UI  ←HTTP→ 本地 FastAPI 后端
        （上传文件 / 手动触发 / 文字状态登记 / 产物查看与下载 / git pull 同步）
```

### 调度时间（北京 = UTC+8，GitHub cron 用 UTC）
| 任务 | 北京 | UTC |
|---|---|---|
| ③ 明日开标提醒 | 09:00 | 01:00 |
| ⑤ 国学自媒体 | 16:00 | 08:00 |
| ④ 银发康养自媒体 | 17:00 | 09:00 |
| ② 日招标筛选 | 18:00 | 10:00 |

已知局限与兜底：Actions 定时可能延迟数分钟、仓库长期无 push 可能暂停 → 工作台提供"手动运行"；后续可选本机 launchd 双保险。

## 四、关键设计决策

1. **关键词可配置**：投标词（EPC/PC/施工/风电/煤电/光伏/电缆）、自媒体词各自独立配置，工作台可编辑。
2. **去重**：① 项目名称规范化去重；② 对主表+历史去重；③ 开标时间=明日。
3. **爆款数据"尽力抓取+AI降级"**：每平台一个适配器（公开搜索页/热榜 JSON 尽力取 标题/作者/赞/评/藏/转/链接），抓不到则标记"降级"，由 DeepSeek 结合趋势生成候选并注明来源 → 保证每天有产出、不静默失败。
4. **状态文字登记**：工作台登记框输入如"XX风电项目 已投 中国电建"，解析后写入主表。
5. **推送格式**：Server酱不能发附件 → Markdown 表格推送，.xlsx/.json 存仓库可在工作台下载。
6. **密钥安全**：SCKEY / DeepSeek Key 只在本地 `.env`(gitignore) 与 GitHub Secrets。
